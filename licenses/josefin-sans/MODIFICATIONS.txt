Modifications to josefin_sans_regular.ttf
=========================================

The SIL Open Font License permits modification and does not require this notice,
but it is recorded for the same reason `special-elite/MODIFICATIONS.txt` in this
repository is: a binary font file carries no diff, so without a written record a
future re-download of the upstream release would silently undo the fix.

The bundled copies of this font (mobile/src/main/res/font/josefin_sans_regular.ttf
and wear/src/main/res/font/josefin_sans_regular.ttf) have been modified from the
upstream release at https://github.com/google/fonts/tree/main/ofl/josefinsans.
Only the vertical metrics were changed; no glyph outline, character mapping, name
table or Reserved Font Name was touched.

  hhea.ascent           750  ->   851
  hhea.descent         -250  ->  -149
  hhea.lineGap            0  ->     0   (unchanged)
  OS/2.sTypoAscender    750  ->   851
  OS/2.sTypoDescender  -250  ->  -149
  OS/2.sTypoLineGap       0  ->     0   (unchanged)
  OS/2.usWinAscent     1242  ->  1096
  OS/2.usWinDescent     324  ->   233

Why
---

Every renderer centres a line of text by its line box, and this is the one font in
this pass whose box centre sat *below* its own capitals rather than above (-0.101
em) - upstream's ascent/descent split the one-em box roughly evenly (750/250) while
the letterforms themselves sit noticeably higher within it, so text in this face
read as sitting low in a centred pill rather than high.

The correction centres the box on the font's flat capital letters - E, F, H, I, L -
which for this font's lining-style numerals also centres the digits, to within a
few thousandths of an em.

ascent + |descent| is unchanged (1000 units, exactly this font's 1000-unit em), so
line height, spacing, wrapping and every reserved height are the same as upstream;
only where the ink sits inside that box moves. The flat-cap band now lands within
0.0001 em of the box centre.

usWinAscent/usWinDescent were narrowed to the font's real ink extents
(head.yMax/yMin), which upstream's values exceeded by a wide margin.

Pinned by BundledFontMetricsTest, so a re-download from upstream fails the build
rather than silently reverting the fix.
