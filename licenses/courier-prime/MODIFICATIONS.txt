Modifications to courier_prime_regular.ttf
==========================================

The SIL Open Font License permits modification and does not require this notice,
but it is recorded for the same reason `special-elite/MODIFICATIONS.txt` in this
repository is: a binary font file carries no diff, so without a written record a
future re-download of the upstream release would silently undo the fix.

The bundled copies of this font (mobile/src/main/res/font/courier_prime_regular.ttf
and wear/src/main/res/font/courier_prime_regular.ttf) have been modified from the
upstream release at https://github.com/quoteunquoteapps/CourierPrime. Only the
vertical metrics were changed; no glyph outline, character mapping, name table or
Reserved Font Name was touched.

  hhea.ascent          1600  ->  1744
  hhea.descent         -700  ->  -556
  hhea.lineGap            0  ->     0   (unchanged)
  OS/2.sTypoAscender   1600  ->  1744
  OS/2.sTypoDescender  -700  ->  -556
  OS/2.sTypoLineGap       0  ->     0   (unchanged)
  OS/2.usWinAscent     1900  ->  1827
  OS/2.usWinDescent     800  ->   526

Why
---

Every renderer centres a line of text by its line box, so where a font's ink sits
inside that box is the font's decision, not the app's. This monospace typewriter
face's box centre sat 0.070 em below its own capital letters (the opposite
direction from most of the other faces corrected in this pass), which read as text
sitting low rather than high in a centred pill.

The correction centres the box on the font's flat capital letters - E, F, H, I, L -
which for this font's lining-style numerals also centres the digits, to within a
few thousandths of an em.

ascent + |descent| is unchanged (2300 units in this font's 2048-unit em - the extra
headroom above one em is original to this font, not something this fix introduced),
so line height, spacing, wrapping and every reserved height are the same as
upstream; only where the ink sits inside that box moves. The flat-cap band now
lands within 0.0002 em of the box centre.

usWinAscent/usWinDescent were narrowed to the font's real ink extents
(head.yMax/yMin), which upstream's values exceeded.

Pinned by BundledFontMetricsTest, so a re-download from upstream fails the build
rather than silently reverting the fix.
